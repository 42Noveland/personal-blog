用了几个月之后，我对 Agent 类工具的定位变了：**它不是搜索框，是一个有手有脚、有记忆的同事**。真正提升效率的不是它多会聊天，而是它能不能替我把一串琐事做完。

## 我实际在用的几件事

- 服务器运维：登录、看端口、改 nginx、拉起后台服务，全程不用我手敲命令；
- 文档整理：把散落的聊天记录、报告整合成能检索的笔记库；
- 重复劳动：批量下载、格式转换、爬取整理，写完就丢给 Agent 跑。

## 关键是「技能」而不是「提示词」

一次性任务用提示词没问题，但凡是会重复发生的流程，都应该沉淀成技能（skill）：一段可复用的操作说明，包含踩过的坑、验证过的命令、收尾检查项。

比如"在这个服务器上部署一个 Node 服务"这件事，我的技能里写着：

1. 用 `setsid nohup ... < /dev/null &` 脱离 SSH 会话，否则命令看起来会卡死；
2. `pkill -f` 会匹配到自己的 SSH 命令行，杀进程要用 `ss -tlnp` 取 PID；
3. 完事必须验证端口在听、接口能返回 200。

这些细节写进技能之后，下次它就不用重新踩一遍。

## 一点边界感

自动化最危险的地方在于**它真的会执行**。所以我的习惯是：

> 破坏性操作先备份，公网服务先限流，密钥从不写进对话。

工具越顺手，越需要给自己划红线。
