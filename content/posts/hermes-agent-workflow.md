用了几个月，我对 Agent 类工具的定位变了：聊天只是入口，它真正的位置更像一个能连 SSH、能跑脚本、有记忆的同事。真正省事的不是它多会聊，而是它能不能替我把一串琐事从头做完。

## 我实际在用的几件事

服务器上的活最省心：登录、看端口、改 nginx、拉起后台服务，全程不用我敲命令。然后就是各种整理——散在各处的聊天记录、报告，收拾成能检索的笔记库。剩下的都是重复劳动：批量下载、格式转换、爬取整理，流程写一次，以后丢给它跑。

## 关键是「技能」而不是「提示词」

一次性任务用提示词没问题，但凡是要重复发生的流程，都值得沉淀成技能（skill）：一段可复用的操作说明，把踩过的坑、验证过的命令、收尾检查都写进去。

比如"在这个服务器上部署一个 Node 服务"这件事，我的技能里写着三条：

1. 用 `setsid nohup ... < /dev/null &` 脱离 SSH 会话，否则命令看起来会卡死；
2. `pkill -f` 会匹配到自己的 SSH 命令行，杀进程要用 `ss -tlnp` 取 PID；
3. 完事必须验证端口在听、接口能返回 200。

这些细节写进技能之后，下次就不用重新踩一遍。

## 一点边界感

自动化最危险的地方在于，它真的会执行。所以我的习惯是：

> 破坏性操作先备份，公网服务先限流，密钥从不写进对话。

工具越顺手，越需要给自己划红线。
