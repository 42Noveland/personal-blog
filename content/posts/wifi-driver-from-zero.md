市面上讲 802.11 的资料要么停在协议框图，要么直接甩给你一份十万行的厂商驱动。真正想搞明白「一帧数据是怎么从应用层走到空口的」，最好的办法还是自己写一个。

## 实验台搭起来了

目标很朴素：一个能 `iw dev` 认出来、能扫描、能连接 WPA2、能 ping 通的驱动。为了让实验可复现，我把驱动挂在一块虚拟 PCI 设备上，避免折腾真机固件。

### 分层与接口

Linux 无线子系统大致是这样分的：

| 层次 | 职责 | 我们的位置 |
|:--|:--|:--|
| cfg80211 | 用户态配置接口 | 注册 wiphy |
| mac80211 | MLME、队列、聚合 | 实现 ieee80211_ops |
| 驱动 | 硬件寄存器操作 | 本文的主角 |
| 固件/硬件 | 射频、收发 | 用虚拟设备替代 |

### 扫描是怎么完成的

扫描并不是「发一个请求、等一个回复」这么简单。驱动要做的是：

1. 组装 Probe Request，把 SSID 列表、速率集、信道填进去；
2. 逐个信道下发，每个信道停留 `dwell time`；
3. 收包并把 Probe Response 往上抛给 mac80211；
4. 最后用 `ieee80211_scan_completed()` 收尾。

第一步的坑是**时序**：如果 `sw_scan_start` 之后立刻调用 `scan_completed`，mac80211 会认为扫描空转，用户态看到的结果永远是空的。

## 密钥协商踩的两个坑

WPA2 的四次握手由 mac80211 和 wpa_supplicant 配合完成，驱动只需要在收到 EAPOL 帧时正确向上转发。我在这里卡了整整一个晚上：

```c
/* 错误示范：直接把 skb 交给协议栈，忘了标记为 EAPOL */
netif_rx(skb);

/* 正确做法：明确告诉 mac80211 这是管理/控制帧 */
ieee80211_rx_irqsafe(hw, skb);
```

另一个坑是**加密位**：硬件加密关闭时，驱动必须让 mac80211 自己解帧；如果两边都以为对方在处理，表现就是「握手成功但 ping 不通」。

> 调试无线最有效的办法不是看日志，是用 `tcpdump -i wlan0 -y IEEE802_11_RADIO` 抓空口帧，然后逐字段对协议。

## 结果

最终跑下来：

- 扫描：`iw dev wlan0 scan` 能列出周围所有 AP；
- 连接：WPA2-PSK 握手一次通过；
- 吞吐：`iperf3` 单向 **309–365 Mbps**（虚拟设备，无真实射频瓶颈）。

代码和实验步骤都留了记录，下次再做第二块网卡时可以直接复用这套脚手架。
