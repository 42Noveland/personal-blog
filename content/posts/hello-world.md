这是第三次自建博客了。前两次分别死在「主题调了三周、一行字没写」和「服务器到期忘了续费」上。

所以这次的目标定得很死：

- **写作优先**：Markdown 文件就是全部真相，备份等于 `cp -r content/`；
- **零依赖**：后端只吃 Node 标准库，`node server.js` 就能跑，没有 `npm install` 的等待和供应链风险；
- **可扩展**：想要的功能写成插件，热插拔，不改内核一行代码。

## 为什么不用现成的

现成的方案都很好，只是不太合我的脾气。我需要的东西其实很小：一个列表页、一个文章页、一个能写字的后台。剩下的——目录、评论、浏览量——我更希望它们是**可拆卸的零件**，而不是内核里长出来的器官。

于是有了现在这套结构：

```
content/posts/*.md   ← 内容（文件即数据）
themes/<name>/       ← 主题（只改 CSS 变量）
plugins/<name>/      ← 插件（钩子 + 自有路由 + 自有 UI）
lib/                 ← 内核（约 2000 行，零依赖）
```

## 接下来

先把之前散落在各处的笔记搬过来，然后再慢慢把插件补齐。写字这件事，工具越安静越好。

> 一个人真正需要的博客功能，大概是 Markdown 加一个输入框。

如果你也在纠结要不要自建，我的建议是：**先写十篇，再决定要不要折腾引擎**。
