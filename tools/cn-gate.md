# 中文发布门禁（cn-gate）

发布中文文章前跑一遍的**确定性检查**：不调模型、不联网、零依赖（只用 Node 标准库）。
它回答的是「这篇稿子踩了哪几条已知的机器腔」，不是「这篇是不是 AI 写的」。

```sh
node tools/cn-gate.mjs content/posts/xxx.md          # 出报告（不拦）
node tools/cn-gate.mjs content/posts/xxx.md --gate   # 门禁模式：不通过 → 退出码 1
node tools/cn-gate.mjs content/posts/xxx.md --json   # 机器可读（含全部指标与命中项）
node tools/cn-gate.mjs content/posts/xxx.md --min 85 # 自定义分数线（默认 75）
```

## 装成 pre-commit 钩子（仓库本地，不动全局）

```sh
sh tools/install-git-hooks.sh
```

装好后，`git commit` 时只要暂存区里有 `content/posts/*.md` 的新增/修改，就会自动跑门禁；
不通过则提交被拦（提示改法），确需跳过用 `git commit --no-verify`。其它文件不受影响。

## 检查什么

| 级别 | 规则 | 说明 |
|---|---|---|
| P0（直接拦） | 翻案句（不是…而是…／并非…而是…／与其说…不如说） | 先立一个读者没有的误解再推翻，是最典型的机器腔 |
| P0（直接拦） | 套话黑话 ≥2 处（值得注意/综上所述/赋能/助力/彰显…） | 换具体动作、数字，或直接删 |
| P1 | 弱式翻案句（不是…，是…）、冒号密度 >20/千、破折号 >1.5/千、粗体当装饰 >1.5/千 | 密度类阈值都按人类样本校准过 |
| P1 | 句长 CV <0.6、短句占比 <8%、单句段 >80%、人称痕迹 <5/万字、结尾口号化 | 节奏与「像不像人在说话」 |
| P2 | 机械序号段首 ≥3 处、没有跟读者说话（第二人称 0）、对称三点式偏多、连续同头句 | 单独出现不算病，成串出现才提 |
| INFO | 4-gram 高频复读 | 技术文专有名词天然复读，只提示不扣分 |

打分：100 分起，P0 −12、P1 −6、P2 −3、INFO 0；**通过条件 = 无 P0 且分数 ≥ 分数线（默认 75）**。

## 阈值怎么来的（重要）

阈值不是拍脑袋定的，是拿三份同题材样本实测校准的：

| 样本 | 校准前 | 校准后 |
|---|---|---|
| 人类手写的中文技术博客（参照） | 43 分 ❌ | **97 分 ✅** |
| 本次博客文章的条目化「改前笔记」 | 64 分 ✅（反了） | **70 分** |
| 博客文章（类人化改写后） | 79 分 ❌ | **91 分 ✅** |

校准前的版本把人类样本判得最低——**任何"AI 味检测"都必须先拿人类文本做对照，否则很容易把正常的中文写作习惯（冒号、单句段、专有名词复读）当成机器腔**。改规则时请重新跑这三份样本，确认排序不变。

## 已知边界

- 它是**清单式门禁**，不是检测器：过了不代表"像人"，只代表"没踩这些已知的坑"。
- 规则针对中文；英文稿的阈值未校准。
- 密度类规则对**文体**敏感：公告、API 文档这类条目化文本天然低分，别用同一把尺子。
- 与量化体检（PPL/文体计量/判官）互补：门禁管"发布前拦明显毛病"，体检管"方向和幅度"。
